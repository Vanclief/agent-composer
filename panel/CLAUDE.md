# panel/: the agc control panel

React 19 + TypeScript (strict) + Vite, Tailwind v4, shadcn/ui (new-york, zinc),
lucide-react, TanStack Query, react-router v7, xterm.js. agc embeds the build
(`panel/dist`) and serves it at `/panel/`; the API is same origin under `/api`.

Several agents build screens here in parallel. Stay inside your directory and
the panel stays conflict-free.

## Design rules

- Follow `/Users/vanclief/.claude/skills/rtsdesign/SKILL.md`: icons, slots,
  chips and numbers instead of sentences; explanations go in tooltips.
- Modes are a vertical list in the sidebar; adding a mode is one entry in `MODES`.
  In Talk mode the sidebar lists every channel under Channels (`ChannelRows` in `src/features/messages/ChannelRows.tsx`, mounted by the shell), linking to `/messages/<name>`; see Talk mode below.
  `ModeSwitch` takes an optional `badges` slot per mode (Talk: the unread total).
- **One icon per concept:** import from `@/components/concept-icons`
  (`conceptIcons.task`, `.sandbox`, `.brief`, `.cpu`, `.memory`, `.image`,
  `.repo`, `.ref`, `.setup`, `.secret`, `.env`, `.volume`, `.channel`,
  `.savedSpec`, `.terminal`, `.message`, `.human`, `.raw`). Never pick a
  different Lucide icon for one of these. A new concept is added there first.
- **Statuses are verbatim:** render `<StatusPill status={task.status} />`
  or `<StatusPill status={sandbox.status} detail={sandbox.status_error} />`.
  Never derive, map or relabel a status in the UI. If a status is wrong, the
  backend has to change. The pill's look follows the rtsdesign tiers
  (`data-tier`): `lit` for alive (running: filled green; starting/stopping:
  pulsing blue; review: filled amber), `off` for ended well (done, stopped:
  the green shape turned off, a dim hollow ring), `attention` for died or
  needs a hand (failed, crashed: lit red triangle, the only red on screen),
  `idle` for not started (open: hollow grey). A done thing never looks as
  bright as a running one; a dead thing never looks like a done one.
- **Lists are rows, not cards:** a list item is a flat row with a hairline
  separator, no colored border (that is for the selected item and for
  grouping panels). Left to right: the status light, the name in normal
  weight, then the rest as dim text in a fixed order. Chips in a row are
  only for things you click or things lit (a live count, a warning); a
  model name or a person is plain muted text. Franco on the task list of
  2026-11-01: equal violet cards with six chips each were "harder than it
  should" be to read.
- **Empty states say why in place:** use `<EmptySlot onAdd={…} label="Add …" />`
  for a fillable slot, or `<EmptySlot reason="Sandbox stopped" />` when it can't
  be filled. A disabled control says why in its own label ("Create: needs a
  title"), never only in a tooltip.
- **Backend errors are shown verbatim:** every API failure is an `ApiError`
  whose `message` is the server's text. Render it with
  `<ErrorText error={query.error} />` (or `errorMessage(e)`), in place,
  never rephrased, and never only as a toast.
- `<IconChip icon={conceptIcons.memory}>4 GB</IconChip>` for icon + mono
  values, paths and ids.
- **Avatars:** `<Avatar name size human? presence? />` (`@/components/avatar`,
  sizes `xs` 16, `sm` 20, `md` 28, `lg` 40) is a deterministic identicon
  hashed from the name (FNV-1a → seeded shapes in the concept hues, never
  the status hues; `data-seed`, `data-shapes`), so a name looks the same
  everywhere. A thin ring says who: human pink, agent or task violet; `agc`
  gets a neutral grey mark (`data-kind` `human`/`agent`/`agc`). With
  `presence` set, a `<PresenceDot online />` (`data-testid="presence"`,
  `data-online`, `data-tier`) sits at its bottom-right: a filled emerald
  dot (tier `lit`) or a hollow grey ring (tier `off`). Used in the channel
  header, the Agents list and page (dot lit only when `awake`; the word
  stays in its pill), the task header's manager and owner (xs) and the top
  bar's `@me` (`data-testid="me"`).
- Compact zinc look, dark by default (light via the sidebar toggle). Use the
  shadcn components in `@/components/ui` (button, card, badge, dialog,
  alert-dialog, input, textarea, label, tabs, tooltip, toggle, toggle-group,
  switch, select, separator, scroll-area, dropdown-menu, sonner, skeleton,
  command).

## API

- `@/api/client`: `api` (typed openapi-fetch client for everything in
  `docs/openapi.yaml`), `unwrap(api.GET(…))`, `apiFetch` for routes not in
  the spec, `ApiError`, and the `TaskSpec` (a sandbox's environment block),
  `SavedSpec` and `Secret` types.
- `@/api/tasks` (ADR 0008): `TaskView`, `SandboxView`, `SandboxRequest`
  (the spec fields inline plus `command`), `CreateTaskRequest`, and the
  `tasks.*`/`sandboxes.*` calls. Hand-typed until the OpenAPI spec has them.
  A task's `status` (`open`, `running`, `review`, `done`) is computed by the server; a
  sandbox's (`starting`, `failed` with `status_error`, `running`, `stopped`,
  `unknown`) is read live. `{id}` accepts an id or a name everywhere.
  `notify` (boolean on `TaskView`; optional on `CreateTaskRequest`, default
  `true`) turns the "Task started" / "Task done" toasts and chime on for that
  task. The create dialog sends it from "Notify me" in the Order card; the task
  header shows a bell chip when it is on.
- Acceptance (ADR 0010): `TaskView` carries `accept` (the criteria, may be
  empty), `delivered_at` (set by the agent's delivery, cleared by a reject),
  `summary` (the last delivery's, kept after a reject) and `accepted_by`;
  `CreateTaskRequest` takes `accept`. `review` means delivered and waiting.
  The create dialog's Order card has "Accepted when" (one criterion per line,
  empty lines dropped). The Brief tab shows the criteria as unchecked boxes
  under "Accepted when" (hidden when empty) and a Summary card with
  "Accepted by <name> <when>" once done. The header shows the amber `review`
  pill, a "Delivered <when>" chip, and Accept (confirms "Accept and stop N
  running sandboxes", or "Accept" when none run) and Reject… (a required
  "Why") until done. `by` is the signed-in name (`humanName()` in
  `src/features/messages/identity.ts`). The list sorts `review` first.
- `@/api/hooks`: tasks `useTasks` (polls every 5s, or 30s while the live
  event stream is connected; sandboxes embedded newest first), `useTask(nameOrId)`, `useCreateTask` (returns at once; an
  optional `sandbox` comes back `starting`), `useDeliverTask` (`{ref, summary}`),
  `useAcceptTask` (`{ref, by}`), `useRejectTask` (`{ref, by, why}`), `useDeleteTask`
  (deletes its sandboxes too), `useAllocate(task)` (201, `starting`, then
  `running`); sandboxes `useSandboxes`, `useSandbox(nameOrId)`,
  `useStopSandbox`, `useStartSandbox`, `useDeleteSandbox`; terminals
  `useTerminals(sandbox, enabled)`, `useStartTerminal(sandbox)`; `useSpecs`,
  `useSpec`, `useSaveSpec`, `useDeleteSpec`, `useSecrets`, `useChannels`,
  `useJoin`, `useLeave`, `usePostMessage`, and `useChannelMessages(channel)`
  (a live feed: read, then a long-poll wait loop), `useParticipants(channel)`.
  Every task or sandbox mutation refreshes both. Query keys live only in
  `queryKeys`.
- `@/api/msg`: messaging types and calls (`/api/msg/join|leave|post|read|wait|channels|participants`),
  hand-typed from `messaging/httpapi/httpapi.go`. Join answers 409
  `name @x is already in use` while the name is held.
- `@/api/terminals`: terminal types, `terminals.list/start`, and
  `terminalSocketURL(sandbox, job)`, all under `/api/sandboxes/{id}/terminals`.
  A sandbox allocated with a `command` runs it as the job `agent`. Binary frames carry bytes both ways; send
  the text frame `{"type":"resize","rows":N,"cols":N}` to resize. The server
  closes with reason `job completed` when the program exits.
- After `docs/openapi.yaml` changes, run `npm run types` and commit
  `src/api/schema.d.ts`. `npm run check` fails while it is stale.

## Live events

`GET /api/events` is a server-sent events stream (`text/event-stream`). Each
event has `event: <type>`, `data: <json>` and an `id` (the event number); the
server sends a comment every 20s as a heartbeat. The panel does not rely on
replay: after a drop it refetches tasks, sandboxes and channels.

| Type             | `data`                                    | Sent when                                                                                                                                  |
| ---------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `task.created`   | `{ "task": TaskView }`                    | a task is created (after its sandbox, if any, is allocated)                                                                                |
| `task.done`      | `{ "task": TaskView, "summary": string }` | a task is accepted; `summary` is the task's delivery summary, else the last message in `#<task>` from neither a human nor `agc`, else `""` |
| `sandbox.status` | `{ "sandbox": SandboxView }`              | every status change: starting→running, →failed, stop, start, and delete (with status `"deleted"`)                                          |
| `message.posted` | `{ "message": Message }`                  | a message is posted in any channel                                                                                                         |
| `agent.state`    | `{ "agent": AgentView }`                  | every agent state change: wake (asleep→waking, then →awake) and sleep (awake→asleep); mock only until the Go side exists                   |

- `@/api/events` (`useLiveEvents(onEvent)`): the app's one `EventSource`,
  opened by the shell (`src/shell/layout.tsx`). Each event invalidates the
  queries it changes (tasks and sandboxes roots for task and sandbox events;
  channels and participants for messages, and the message is appended to
  its channel's feed; agents and sandboxes roots for `agent.state`), so every page refreshes itself. Don't open another
  stream in a feature; read the cache.
- `@/api/live`: whether the stream is connected (`useLiveConnected`) and
  `livePollMs`, the polling fallback for tasks, sandboxes and channels: 5s
  without the stream, 30s with it. EventSource retries network drops itself;
  when it gives up (an HTTP error) the panel reopens it with backoff, 1s up
  to 30s.
- Top bar: a dot, green `live` while connected, amber `live: reconnecting`
  otherwise (`data-testid="live-status"`, `data-state`), and the speaker
  toggle (`data-testid="sound-toggle"`, localStorage `agc.panel.sound`
  `on`/`off`, default on).
- Notifications (`src/shell/notifications.tsx`), only for tasks with
  `notify` true: a top-right toast "Task started" (title, assignee (model),
  sandbox) on `task.created`, and "Task done" (title, the summary's first 240
  characters, "Show more") on `task.done`, each with an "Open" action to
  `/tasks/<name>`. Both play a two-tone Web Audio chime (`src/shell/sound.ts`,
  no asset); before the page's first click or key press the browser keeps
  audio suspended, so the chime waits for it.

## Agents (persistent agents, proposal; no Go side yet)

- `@/api/agents`: `AgentView` (`name`, `role`, `kept`, `harness`, `model`,
  `owner`, `state`, `home`, `tasks: {name, status}[]`,
  `conversations: {channel, last_at}[]`, `last_active_at`, `created_at`),
  `CreateAgentRequest {role, harness?, model?}`, `KeepAgentRequest {name,
role?}`, hand-typed from the proposal and served only by the mock. Hooks:
  `useAgents`, `useAgent(name)`, `useCreateAgent` (201, the numbered agent
  `<role>-<n>`, asleep, `home: null`), `useKeepAgent(name)` (names or
  renames; the answer carries the new name), `useWakeAgent(name)`,
  `useSleepAgent(name)`. Agent mutations refresh agents and sandboxes.
- An agent is born numbered from its role (`reviewer-3`, `kept: false`);
  Keep… names it (`ada`, `kept: true`) and may change its role; Rename… is
  the same dialog for a kept agent. `state` is `awake`, `asleep` or
  `waking`, shown verbatim with `StatusPill` (emerald, zinc, sky, as
  sandbox `running`, `stopped`, `starting`).
- `/agents` lists awake, then waking, then asleep; numbered names are muted
  with a "numbered" hint, kept ones bold. `/agents/:name` has Wake (asleep),
  Sleep (awake; disabled as "Waking…" while waking), Keep…/Rename…, and the
  cards Home (`/compute/<home>`, or "Not woken yet"), Tasks
  (`/tasks/<name>`, status verbatim), Conversations (`/messages/<channel>`,
  the DM `#<owner>` first) and Identity.

## Talk mode: inbox, unread, notifications

- **Me:** the signed-in name is `useMyName()` (`src/features/messages/identity.ts`,
  localStorage `agc.panel.human`, default `franco`); it follows "Join as…".
  My inbox is the channel `#<me>` (ADR 0009 item 5).
- **Sidebar** (`ChannelRows`): a pinned first row "Inbox" (inbox icon,
  `data-testid="inbox-row"`) for `#<me>`, shown even before it has a message;
  then the group "Tasks" (channels named after a task from `useTasks`), then
  "Other" (`role="group"`, `aria-label` the group name). Each row has an
  `UnreadBadge` (`data-testid="unread-badge"`, `data-mention`) and is bold
  while unread (`data-unread`); the badge is pink when an unread message
  mentions `@<me>` (whole word). The Talk row in the mode switch shows the
  total, pink when any unread message mentions me.
- **Read state** (`src/features/messages/unread.ts`, `useUnread()`,
  `markRead`): localStorage `agc.panel.read` maps `#channel` → last read
  message id. `ChannelView` (Talk page and a task's Messages tab) marks every
  message it shows read. A channel whose `last_id` is past its cursor is read
  from the cursor (`queryKeys.unread`) to count messages not from me, so
  `message.posted` (which refreshes channels) bumps counts without a reload.
  A never-opened channel counts all its messages.
- **Notifications** (`src/features/messages/notifications.tsx`, wired next
  to the task ones in the shell): a top-right toast "Inbox" or "Mentioned
  you" (`data-testid="toast-message"`, `data-id`, `data-channel`) with the
  sender, channel and the body's first 160 characters, an "Open" action to
  `/messages/<channel>`, and the chime (speaker toggle applies). Only for
  messages in `#<me>` or mentioning `@<me>`; never for my own messages or
  for the channel I am looking at. Everything else only bumps badges.
- **Presence** (`src/features/messages/presence.ts`): participants carry
  `online` and `last_seen_at` (hand-typed in `@/api/msg`; the backend is
  adding them). `usePresence(channel)` reads `GET /api/msg/participants`
  every 15s (and on `message.posted`, which invalidates the same query) and
  returns name → `{online, last_seen_at}` (a name held twice is online if
  either is). The channel header (`ChannelView`'s members strip) shows each
  member as an avatar with its dot and the tooltip `@name · online` or
  `@name · last seen 3 min ago`. Not yet in the message headers
  (`MessageList`) or the sidebar rows (`ChannelRows`).
- **Inbox page:** `/messages/<me>` is the ordinary channel view titled
  "Inbox #<me>", with the line "Your inbox: agents and tasks escalate here"
  (`data-testid="inbox-header"`) and, when empty, an empty slot saying so.

## Serving from agc

`make panel` (repo root) builds `dist/`, and `go build` embeds it
(`panel/embed.go`). Without a build, agc answers `/panel/` with 503
`control panel not built: run make panel`. `AGC_PANEL_DIR=panel/dist agc …`
serves a build from disk without rebuilding agc.
